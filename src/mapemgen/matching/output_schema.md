# Output Schema — `mapped_evidence.json`

> The matching stage's deliverable, and the **interface to downstream evidence
> fusion (Task 3)** — confidence is already folded into selection via `final_score`. This document is the contract: field
> names, types, and meanings. Generated by `matching_engine.py`.

---

## Top-level object

```json
{
  "mapped_evidence":    [ <FieldRecord>, ... ],
  "manual_review_items":[ {"target": str, "reason": str}, ... ],
  "validation_report":  [ <ValidationEntry>, ... ],
  "forbidden_elements": [ {"target": str, "reason": str, ...}, ... ],
  "warnings":           [ <Warning>, ... ],
  "summary":            { "total_fields": int, "matched": int,
                          "manual_review_required": int, "pending_transform": int, ... }
}
```

| key | type | meaning |
|---|---|---|
| `mapped_evidence` | list | one record per resolved MAPEM field — the main payload |
| `manual_review_items` | list | fields needing a human (e.g. a required group missing) |
| `validation_report` | list | per-field audit trail (status, chosen facts, corroboration) |
| `forbidden_elements` | list | C-Roads-prohibited elements detected |
| `warnings` | list | run-level issues (OSTN15 grid missing, bad inputs) |
| `summary` | object | counts by status |

---

## `FieldRecord` (each item of `mapped_evidence`)

```json
{
  "target_path":     "mapData.intersections[0].refPoint.lat",
  "value":           538076070,
  "population_mode": "geometry_derived",
  "rule_applied":    "mapData.intersections[].refPoint.lat",
  "source_facts":    ["f_geo", "f_crs"],
  "transforms_run":  ["polygon_centroid","bng_to_wgs84_OSTN15","take_lat","wgs84_to_int_1e7"],
  "priority_used":   "P1",
  "confidence":      "high",
  "conflict":        { ... see conflict_rules.md ... },
  "corroborating":   ["f_geo2"],
  "status":          "matched",
  "notes":           ""
}
```

| field | type | meaning |
|---|---|---|
| `target_path` | str | concrete MAPEM path with instance indices resolved (`[0]`, `[1]`...) |
| `value` | any | the mapped value (int/float/str/list/dict), or `null` if unresolved |
| `population_mode` | str | how it was obtained (constant, client_configured, geometry_derived, ...) |
| `rule_applied` | str | the template path from the rules (`[]` not yet indexed) |
| `source_facts` | list[str] | fact_id(s) that produced the value; multiple = AND groups each contributed |
| `transforms_run` | list[str] | transform names applied, in order |
| `priority_used` | str | priority label of the chosen source (P1–F) |
| `confidence` | str | `high`/`medium`/`low`/`n/a` — set by the confidence stage (currently fact-level) |
| `conflict` | object | conflict variable for confidence scoring — see `conflict_rules.md` |
| `corroborating` | list[str] | fact_id(s) that agreed but weren't chosen |
| `status` | enum | `matched` \| `matched_with_conflict` \| `manual_review_required` \| `unresolved` \| `pending_transform` |
| `notes` | str | human-readable explanation when status ≠ matched |

### `status` values (v3 `selected_statuses`)
- **matched** — value selected by `final_score`, no material conflict.
- **matched_with_conflict** — value selected, but other candidates disagreed (see `conflict`).
- **manual_review_required** — needs a human (e.g. a required fact_group missing); see `notes` / `conflict.missing_groups`.
- **unresolved** — candidates existed but none produced a usable value.
- **pending_transform** — matched a source but the transform isn't implemented / payload-shape mismatch. `value` may be raw payload.

(Forbidden elements are reported separately under `forbidden_elements`.)

---

## `conflict` (summary; full spec in `conflict_rules.md`)

Flat fields at the top level (the chosen value's group), plus a `groups`
breakdown and the AND result:

```json
{
  "candidate_count": 3, "agreement_count": 2, "disagreement_count": 1,
  "priority_used": "P1", "priority_spread": ["P1","P2","P3"],
  "max_divergence": 4.995, "divergence_unit": "m",
  "tolerance_applied": 2.0, "field_type": "coordinate", "pending": false,
  "primary_group": "geometry", "all_required_groups_satisfied": true,
  "missing_groups": [], "total_candidate_count": 4, "groups": { ... }
}
```

## `ValidationEntry`

```json
{ "target": str, "status": str, "rule_applied": str,
  "chosen": [fact_id...], "confidence": str, "corroborating": [fact_id...] }
```

## `Warning`

```json
{ "code": str, "severity": "high"|"medium"|"low", "message": str,
  "fact": str (optional) }
```
Codes: `ostn15_grid_missing`, `unknown_fact_name`, `bad_confidence`,
`fact_missing_payload`, `fact_missing_name`, `duplicate_fact_id`, `bad_config_type`.

---

## Notes for downstream (evidence fusion / confidence)

- **Provenance is preserved**: `source_facts` + `corroborating` let fusion trace
  every value back to its facts.
- **Confidence is not final here**: matching emits `conflict` + a fact-level
  `confidence`; the confidence stage refines `confidence` from `conflict`.
- **Honour `status`**: only `ok` records carry a trustworthy `value`. Treat
  `pending_transform` / `manual_review` as not-yet-final.
- **Instance indices** in `target_path` are assigned by the engine in encounter
  order; they're stable within one run but not guaranteed across re-runs if facts
  change.

If fusion needs a field added or renamed, raise it — this schema is the agreed
contract and should change deliberately.
