# MAPEM MVP element-source priority dictionary


## Priority table

| MAPEM element | Population mode | Required fact types | P1 source | P2 source | P3 / fallback | Manual-review trigger | Validation rule | Short rationale |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `map.intersections[].laneSet[]` | `geometry_derived` | `controlled_lane_candidate`<br>`crosswalk_lane_candidate`<br>`lane_candidate`<br>`signal_controlled_lane_evidence` | `site_plans_and_cad_files -> cad_drawing` | `site_plans_and_cad_files -> annotated_drawing_pdf` or `embedded_layout_in_specification_pdf`; use configuration sources to confirm controlled scope | Manual geometry review; survey or LiDAR may support geometry when supplied | Controlled lanes or crossings cannot be resolved; geometry sources disagree; roundabout internal lanes remain ambiguous | Include every fused traffic-light-controlled lane individually and retain geometry plus control provenance | Geometry delineates lanes, while configuration evidence decides which candidates belong in the controlled intersection model. |
| `map.intersections[].laneSet[].laneID` | `system_generated` | `lane_candidate`<br>`stable_lane_ordering_rule` | `project_or_client_configuration -> stable_lane_ordering_rule`, applied after extraction | CAD geometry may support deterministic ordering but is not the final ID source | Manual ordering confirmation | Ordering tie; unresolved geometry; lane candidate set changes after ID generation | Every lane has an ID; IDs are unique within the intersection and deterministic | MAPEM lane IDs are generated identifiers, not labels to search for in CAD. |
| `map.intersections[].laneSet[].ingressApproach` | `geometry_derived` | `lane_direction_candidate`<br>`stop_line_candidate`<br>`road_arm_candidate`<br>`approach_group_candidate` | CAD geometry, inbound direction, stop line, and road-arm grouping | Annotated drawing or embedded layout; MOVA schematic or UTC link description when it maps to the lane | Manual approach assignment | Inbound direction uncertain; stop line conflicts with direction; road-arm grouping ambiguous | Every ingress lane has a consistent approach assignment and asserts `directionalUse.ingressPath` | Ingress approaches are grouped by arm and inbound direction, with special handling for crossings and successive lanes. |
| `map.intersections[].laneSet[].egressApproach` | `geometry_derived` | `lane_direction_candidate`<br>`stop_line_candidate`<br>`road_arm_candidate`<br>`approach_group_candidate` | CAD geometry, outbound direction, conflict-area exit, and road-arm grouping | Annotated drawing or embedded layout; MOVA schematic or UTC link description when it maps to the lane | Manual approach assignment | Outbound direction uncertain; exit geometry conflicts with drawing; road-arm grouping ambiguous | Every egress lane has a consistent approach assignment and asserts `directionalUse.egressPath` | Egress approaches use the same geometry-led grouping principle for outbound lanes. |
| `map.intersections[].laneSet[].laneAttributes.directionalUse` | `geometry_derived` | `classified_lane_direction`<br>`approach_assignment`<br>`stop_line_candidate` | Resolved CAD lane direction and approach assignment | Drawing arrows or MOVA schematic validation | Manual direction confirmation | Approach unresolved; geometry, stop line, and schematic disagree | Populate bits correctly: `ingressPath` for ingress, `egressPath` for egress, both for reviewed bidirectional lanes | This value is derived after approach assignment, not read as an isolated file label. |
| `map.intersections[].laneSet[].laneAttributes.sharedWith` | `evidence_fused` | `shared_use_candidate`<br>`bus_lane_candidate`<br>`cycle_lane_candidate`<br>`pedestrian_shared_use_candidate`<br>`road_marking_or_sign_note` | CAD or annotated drawing markings, signs, and explicit shared layout | Controller configuration, MOVA schematic, or UTC notes | Manual shared-use confirmation | Shared use unclear; sources conflict; primary user unclear | Populate the mandatory bit string even when all bits are zero; retain evidence for asserted bits; reject disallowed bits | Sharing bits need lane-specific evidence and must be coordinated with the primary `laneType`. |
| `map.intersections[].laneSet[].laneAttributes.laneType` | `evidence_fused` | `lane_type_candidate`<br>`vehicle_lane_candidate`<br>`crossing_candidate`<br>`pedestrian_phase_candidate`<br>`cycle_lane_candidate`<br>`bus_lane_candidate` | CAD or annotated drawing classification | Site configuration evidence, especially crossing, pedestrian, cycle, and bus references | Manual lane-type classification | Geometry and control evidence disagree; special facility unclear; evidence missing | Select one supported mandatory lane type and check consistency with `sharedWith` | Geometry provides the visible facility type; control evidence confirms classifications that geometry alone may miss. |
